# Specifications of Runtime Reconfigurable Scenarios

## Reference
* http://wiki.ros.org/actionlib/Tutorials

## Ver 0.1

#### Implementation Details
* Action Server
	* Request:
		* The action server should take a string that represent a file path that ends with `.json` which defines a scenario config in it.
		* The action server should not refer to the root field of the json data extracted from the given file.
		* The action server should check the field of map and route in the json data to validate if it is valid.
	* Result
		* The action server should return a result with condition state.
			* config_not_recognized -3: One or multiple field(s) in the configuration is not recognized.
			* config_not_valid -2: The data format of the config file is invalid.
			* config_not_found -1: No file found by the request path.
			* safe 0: Whether the scenario is completed or not, no safety-related situation had happened.
			* risky 1: Whether the scenario is completed or not, one or more risky situation had happend.  Note that the risky situation may be caused from the scenario or the behavior.
			* collided 2: Whether the scenario is completed or not, one or more collision event have been detected.
	* Feedback:
		* The action server should return a feedback message that contains detected agents' id and RSS state.
			* rss_state_red 0: The risk of collision exists on both lateral and longitudinal direction.
			* rss_state_yellow 1: The risk of collision exists on one of lateral and longitudinal direction.
			* rss_state_green 2: The risk of collision doesn't exist.
	* [Preempt action] The action server should check if there is any running scenario when recieving new ScenarioUpdateAction request.  If so, the preempted scenario should be terminated with a result and all agents should be set to initial pose given by the new request config.
* Action Client
	* [Action complete] The action client should be implemented with a script to check if the action is over.  If so, send a new action request or simply cancel request to the action server.

#### Interface

```
// ScenarioUpdateAction.action
string motion_config_file_path
---
int8 validation_result_config_not_recognized=-3
int8 validation_result_config_not_valid=-2
int8 validation_result_config_not_found=-1
int8 validation_result_safe=0
int8 validation_result_risky=1
int8 validation_result_collided=2
int8 validation_result
---
uint8 rss_state_red=0
uint8 rss_state_yellow=1
uint8 rss_state_green=2
string[] agent_ids
uint8[] rss_states

```

* Request:
	* string motion_config_file_path: A file that contains a full configuration of the running scenario.  This file should be generated by script rather than using the file in scenario/data/
* Result:
	* int8 validation_result: An int8 number that represent the result of the requesting validation set.
* Feedback:
	* string[] agent_ids: An vector of string that contains all agents that has been detected in current timestep.
	* int8[] rss_states: An vector of uint8 that contains all rss states of detected agents.  The order is given by agent_ids.
