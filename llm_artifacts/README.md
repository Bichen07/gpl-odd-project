# `llm_artifacts/` — Phase 4 / Phase 5 outputs

This folder is the **single source of truth** that the LLM-cluster-interpretation
pipeline reads from. Everything in here is generated by the analyzer's
`llm_dataset_builder.py` and is **not** committed to git (see `.gitignore`).

## Layout

```
llm_artifacts/
└── <run_id>/                              # e.g. dataset1_3clusters_20260503T1200
    ├── manifest.json                      # batch_id, scenario_id, ego_id,
    │                                      # n_clusters, generated_at, code_sha
    ├── map/
    │   ├── hct_6.xodr                     # copy of the source .xodr
    │   └── hct_6.map.yaml                 # output of xosc_gen map_preprocess
    ├── clustering/
    │   ├── selectedClusteringResult.json  # copy of analyzer output
    │   ├── X_rep.npy                      # MFPCA scores
    │   └── trial_ids.json                 # ordered IDs aligned with X_rep
    └── clusters/
        └── cluster_<label>/               # one folder per HDBSCAN cluster
            ├── medoid.json
            ├── observations.json          # raw Payload Observations of medoid
            ├── trajectory.csv             # xosc_gen-format ground-truth CSV
            ├── meta.yaml                  # xosc_gen-format scenario metadata
            ├── stats.json                 # cluster aggregate statistics
            ├── action_log.yaml            # SimLabeller output (Phase 4 v2)
            └── bev/                       # symlink/copy of bev_output frames
                └── frame_<NNN>.jpg
```

## Generated by

| File | Generator |
|---|---|
| `manifest.json` | `app/analyzer/src/llm_dataset_builder.py` |
| `map/*` | `xosc_gen/scripts/map_preprocess.py` (one-time per `.xodr`) |
| `clustering/*` | Analyzer `clustering()` result (Phase 2 medoid layer) |
| `clusters/*/observations.json` | `controller.get_medoid_observations()` |
| `clusters/*/trajectory.csv` + `meta.yaml` | `app/analyzer/src/sim_labeller.py` |
| `clusters/*/stats.json` | `app/analyzer/src/cluster_stats_builder.py` (Phase 5) |
| `clusters/*/action_log.yaml` | `sim_labeller.py` action classifier (Phase 4 v2) |
| `clusters/*/bev/*` | Phase 3 `bev_renderer.py` |

## Why this layout

- Mirrors the input contract of `xosc_gen/models/labeller.py`:
  `(meta_path, map_yaml_path, gt_trajectory_path)`. Existing code paths can
  consume our `meta.yaml` + `hct_6.map.yaml` + `trajectory.csv` directly.
- One folder per cluster matches the Phase 5 prompt template — each prompt is
  built from one cluster folder.
- Raw `observations.json` is preserved for debugging / fallback so we can
  rebuild `trajectory.csv` without re-querying Payload.
