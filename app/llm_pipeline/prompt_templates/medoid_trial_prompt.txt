<Motive summary guide>
Write 1-3 short paragraphs (blank line between). This is the causal STORY that
connects motives across time — it is NOT a re-listing of `decision_timeline`, and
NOT a single vague sentence.

**One phase = one paragraph.** A phase is a maximal run of consecutive timeline
entries that share the same (or a tightly linked) motive code — e.g. four
`assertive_gap_acceptance` accelerate entries are ONE phase. For a multi-entry
phase, cite ONLY the first and last anchor values (time, speed, d, ttc) — do not
enumerate every intermediate stamp; that is already in `decision_timeline`.
Target ~25-45 words per paragraph (roughly 100-200 words total) — dense, not padded.

Each paragraph covers, in order:
1. WHEN — the phase's time range (first→last stamp of the phase, not every stamp).
2. WHAT+WHY — the ego action(s) under this phase's motive, with intensity + the
   anchor speeds, and WHY this closed code applies (causal locality). Phrase this
   as behavior/intent ("holds speed into a closing gap because…"), not a bare
   number dump.
3. SITUATION — the anchor named-vehicle geometry only (start/end distance, azimuth, gap trend, TTC).
4. LINK — how this phase sets up, changes, or fails relative to the next phase / outcome.

Rules:
- Name closed motive codes explicitly (`assertive_gap_acceptance`, `late_reaction`,
  `brake_release`, `post_clear_hard_brake`, `post_clear_adjustment`, …). Use the
  standard arc phrasing (`pass-first`, `smooth-pass`, `late-yield`, `pass-slowdown`,
  `yield-stop-collision`, `braking-rear-end`) alongside the closed codes.
- State pass/yield order in the first paragraph (give-way brake while not
  behind = yield, including failed overlap; named vehicle behind or hold/accel
  / brake_release-then-continue = pass-first; do not require azimuth BEHIND).
- Quote numbers from context / BEV — but only the anchors for the phase, not a
  restatement of every decision_timeline row.
- Do NOT invent actions absent from context/BEV. Do NOT narrate junction enter/exit.
- The OUTCOME paragraph (collision OR near-miss) is never a one-line summary —
  quote the terminal numbers (Ego speed, named vehicle speed, center-to-center distance,
  named vehicle azimuth relative to Ego heading, and estimated time to collision at
  peak_t) same as the
  collision-anatomy requirement. "Ego yielded, preventing a collision" with no
  numbers is a FAILED output.
- If some ego action is `unclear`, first check common_sense's precedence rules
  (`brake_release` / `post_clear_hard_brake` / `post_clear_adjustment`) — only
  call it `unclear` if evidence is genuinely contradictory or missing, and
  mirror it in open_questions.

Example (good style: concise, phase-based, minimal timestamps):

Ego follows a pass-first arc: it keeps building speed while CuttingIn remains
ahead and the gap tightens, so the opening phase is `assertive_gap_acceptance`
rather than yield. The key causal point is intent under closure: Ego commits to
passing before any meaningful brake response.

When overlap becomes very close on the left, Ego brakes only then, so the
conflict response is `late_reaction`. The near-miss confirms the brake came late
but still avoided contact for this medoid.

After clearance, a short slowdown plus a same-lane turn are post-conflict
stabilization (`post_clear_adjustment` then `post_clear_recovery`), not a new
evasive phase, because CuttingIn stays behind and separation continues opening.
</Motive summary guide>
